# 待并入参谋手册：本地提取层 + 云端决策层（混合架构）草稿

> 状态：待环境切回 Windows 本机后，追加到《云顶之弈_S18_参谋手册.md》。
> 来源：2026-11-12 会话讨论；本机配置 Win11 / 32G 内存 / 索泰 3060Ti 8G / SSD 空闲 150GB。
> 边界不变：本地只读屏幕、不碰游戏进程、不读内存、不做自动点击。

## 1. 分层定位

```
抓帧(现有 capture-lol.ps1, ~0.15s)
   → 本地提取层：把画面读成结构化文本（不出本机）
   → 云端决策层：只收几十字文本，给买牌/人口/装备/站位建议
```
图片不再整帧回传；本地负责"认字读数"，云端负责"判断决策"。

## 2. 本地提取字段（分两类，可靠性不同）

### A. 文字/数字类——OCR 可本地可靠提取
| 字段 | 位置 | 方式 |
| --- | --- | --- |
| 阶段回合（如 4-2） | 顶部 | OCR |
| 等级、经验进度 | 左下 | OCR |
| 金币、血量 | 底部 / 右上 | OCR |
| 商店 5 张：牌名 + 费用 + 羁绊 | 底部商店栏 | OCR + 羁绊词表匹配 |
| 已激活羁绊名 + 层数 | 左侧羁绊栏 | OCR + 词表匹配 |

### B. 视觉图标类——本地小模型不可靠，先留空或回传小图
| 字段 | 难点 | 处理 |
| --- | --- | --- |
| 棋子身份/星级 | 立绘小、特效遮挡 | 先靠牌名词表，存疑裁小图回传 |
| 身上成装/散件 | 装备图标小、彩色 | 图标模板匹配或回传局部图 |
| 站位/对位 | 空间关系 | 仍需看棋盘图 |

## 3. 本地输出结构化模板（喂给云端的就是这段）

```
阶段: 4-2
等级: 8 (经验 0/76)
血量: 80
金币: 29
已激活羁绊: 病毒魔人1, 街头恶魔5, 斗士3, 高级工程师3,
           强袭射手1/2, 战略分析师1/2, 杀手1/2,
           福牛守护者1/2, 源计划1/3
商店:
  1. 吉格斯 4费 [赛博老大, 战略分析师]
  2. 希瓦娜 2费 [魔装机神, 堡垒卫士, 高级工程师]
  3. 薇古丝 4费 [圣灵使者, 裁决使]
  4. 维迦 2费 [赛博老大, 高级工程师]
  5. 蕾欧娜 4费 [幻灵战队, 重装战士]
视觉待确认: 场上棋子星级 / 装备 / 站位
```

云端拿到文本即可做经济、买牌、羁绊缺口判断；只有"视觉待确认"项补一张局部小图。

## 4. 本地模型选型（从轻到重，逐级实测）
1. 先试 Windows 自带 OCR（Windows.Media.Ocr，免下载大模型）：跑数字和牌名，验中文小字号准确率。
2. 不够再上专用 OCR 模型（glm-ocr / deepseek-ocr，Ollama 拉取，2~4GB）。
3. 图标/立绘识别再上 Qwen2.5-VL-3B（Q4，3~4GB，3060Ti 8G 可跑）。
   - 备选：Gemma 4 e4b（4~5GB）、Moondream2 1.8B（~2GB，简单任务）。
   - 7B/8B（Qwen3-VL-8B 等）Int4 占 7~8GB，显存紧，需关其他占显存程序。

## 5. 待实测关键项（动手前先验证）
- 中文牌名/羁绊名在游戏字体下的 OCR 准确率；
- 小字号数字（金币、血量）是否认错；
- 本地提取一张图耗时，对比现在 6~9 秒整帧回传能省多少；
- 3B VLM 对棋子/装备图标的辨认是否够用。

## 6. 速度账（估算，待实测）
- 现状云端链路：抓帧 0.15s + 整帧回传 6~9s + 云端理解生成数秒 ≈ 8~11s。
- 混合架构：抓帧 0.15s + 本地提取（小模型/OCR 数秒）+ 文本回传（极快）+ 云端决策数秒。
- 本地小模型推理 3060Ti 上估 15~30 tok/s；省掉整帧回传，但本地推理本身有数秒，净提升需实测。
- 纯本地端到端（本地看图 + 本地出建议）不推荐：小模型不懂版本 meta，识别准确率也不够。

## 7. 落地顺序（切回本机后）
1. 拿真实对局截图，先跑 Windows 自带 OCR 看数字/牌名准不准；
2. 达标则接结构化模板，不达标再下载专用 OCR / 小 VLM；
3. 实测单张提取耗时与准确率，再决定是否替换整帧回传；
4. 决策层仍留云端大模型。
