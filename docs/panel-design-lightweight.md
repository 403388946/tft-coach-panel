# 云顶之弈参谋面板 · 轻量版（A）设计稿

> 状态：设计稿，待环境切回 Windows 本机后落地。
> 基线：Win11 / 32G 内存 / 索泰 3060Ti 8G / SSD 空闲 150GB；游戏 WeGame 腾讯服，客户端 S18。
> 边界不变：面板只读屏幕、只做展示与手动触发；**不自动点击、不读进程内存、不注入、不切 PIP 虚拟桌面、不提权**。
> 关联产物：`capture-lol.ps1`（只读抓帧）、《云顶之弈_S18_参谋手册.md》、《混合架构方案_待并入手册.md》。

## 1. 设计目标与非目标

### 1.1 目标（MVP，先跑通参谋闭环）
- 一个常驻 main 桌面的轻量侧边栏面板，替代"手动找截图 → 贴对话"的操作；
- 一键触发抓帧（复用现有 `capture-lol.ps1`），把当前局面读成结构化状态；
- 展示局面关键信息 + 云端给出的参谋建议（买牌 / 人口 / 装备 / 站位 / 变阵方向）；
- 识别存疑或本地提取未覆盖的项，允许手动补录；
- 提取层、决策层都以接口形式预留，后期可平滑替换，不改面板骨架。

### 1.2 非目标（本阶段明确不做）
- 不做自动买牌、自动刷新、自动升人口、自动走位、拖阵等任何键鼠动作；
- 不直连 LCU / 本地客户端 API，不解析进程命令行、不读内存、不 Hook；
- 不做常驻托盘后台服务、不做开机自启、不做全局热键钩子；
- 不做完整棋盘图形化拖拽编辑器（P1 再议）；
- 不打包 exe、不做 Electron 桌面应用（那是 C 形态，后期再评估）。

## 2. 合规红线（面板设计必须遵守）

| 类别 | 允许 | 禁止 |
| --- | --- | --- |
| 信息获取 | 调脚本只读抓帧（PrintWindow 优先，黑屏回退 CopyFromScreen）；读本地赛季词表 | 读进程内存 / 模块 / 句柄列表；Hook；注入；读 ACE 相关数据 |
| 对游戏动作 | 仅在面板内显示建议；操作由玩家本人在游戏里完成 | 模拟键鼠、自动点击、自动匹配、自动投降、强杀进程 |
| 权限 | 普通用户权限运行 | 申请管理员提权；改写客户端配置 |
| 运行位置 | main 桌面侧边栏 | 切 PIP 虚拟桌面；后台隐藏运行 |
| 决策来源 | 云端大模型结合版本 meta；可数/可查项走确定性查表 | 面板内置"固定必胜阵容表"替代临场判断 |

## 3. 总体架构与数据流

```
┌─────────────────────────── 轻量面板（main 桌面侧边栏）───────────────────────────┐
│  ① 抓帧按钮 ──▶ ② 本地提取层(预留接口) ──▶ ③ 结构化状态 state ──▶ ④ 决策接口 ──▶ ⑤ 建议区 │
│        │                │                    │                    │                │
│        ▼                ▼                    ▼                    ▼                │
│  capture-lol.ps1    OCR/小模型(待实测)   词表归一化(S18)      decide(state,frame?)  卡片/文本
│  PrintWindow→JPEG   存疑标 unresolved    对齐 board state      MVP=对话贴文本；后期=agent
└──────────────────────────────────────────────────────────────────────────────────┘
```

- **① 抓帧**：复用现有脚本，输出 `%TEMP%\lol_frame.jpg`（1600×900，JPEG q80，约 134~196KB）。
- **② 本地提取层（接口预留，MVP 可空实现）**：把画面读成结构化文本；MVP 阶段先回退到"整帧交云端看图"，提取层达标后再替换。
- **③ 结构化状态**：统一 board state 对象（见第 5 节），所有后续环节只认这个对象。
- **④ 决策接口（抽象函数）**：签名 `decide(state, frame_path?) -> { advice, target_comp?, trait_check?, raw }`。
  - MVP 实现：把 state 文本 + 必要局部小图贴给云端对话；
  - 后期实现：本地 FastAPI agent（羁绊断点复核 + 查表 + 服务端二次校验）。
- **⑤ 建议区**：按卡片展示，标注置信度与存疑项。

## 4. 界面布局

### 4.1 窗口规格
- 形态：侧边栏窗口，建议 **440×760**，可贴屏幕右侧；置顶可选（不强制）；
- 常驻 main 桌面；窗口标题：`TFT 参谋面板`；
- 不依赖游戏窗口位置；抓帧由脚本按窗口标题 `League of Legends` 定位句柄。

## 5. 结构化状态（board state）字段

字段定义 MVP 先做子集；字段缺失即留空，不猜值。

| 字段 | 类型 | 含义 | MVP | 来源 |
| --- | --- | --- | --- | --- |
| `stage` | str | 回合，如 `4-2` | ✅ | OCR / 手动 |
| `level` | int | 等级 | ✅ | OCR / 手动 |
| `xp` | str | 经验进度，如 `0/76` | ✅ | OCR |
| `gold` | int | 金币 | ✅ | OCR |
| `hp` | int | 血量 | ✅ | OCR |
| `streak` | str | 连胜/连败，如 `W3`/`L2` | ✅ | OCR / 手动 |
| `augments` | [str] | 已选海克斯 | ✅ | OCR / 手动 |
| `pending_augments` | [str] | 当前待选 3 个 | ✅ | OCR / 手动 |
| `traits` | [{name, count, breakpoint, short_by}] | 羁绊 + 层数 + 断点 | ✅ | OCR + 词表 + 查表 |
| `shop` | [{name, cost, traits}] | 商店 5 张 | ✅ | OCR + 词表 |
| `emblems` | [str] | 持有纹章 | P1 | 手动 / 图标匹配 |
| `items` | {component, craftable, artifact, support, radiant: [str]} | 持有装备分类 | P1 | 图标匹配 / 手动 |
| `board` | [{unit, star, items, pos:[row,col]}] | 场上棋子 | P1 | 视觉识别 / 手动 |
| `bench` | [{unit, star, items?}] | 备战席 | P1 | 视觉识别 / 手动 |
| `opponent` | {board, note} | 对手信息（后期对位） | P2 | 截图 / 备注 |
| `note` | str | 自由备注 | ✅ | 玩家输入 |
| `unresolved` | [str] | 识别存疑字段清单 | ✅ | 提取层标注 |

**保守原则**：任何字段识别置信度不足或定位失败，写入 `unresolved`，面板置灰标注"待确认"，**不默认填 1 星、不默认无装备、不默认满羁绊**。

## 6. 交互流程

### 6.1 主流程（一次参谋循环）
1. 玩家在备战阶段点 **[重抓帧]**；
2. 面板调 `capture-lol.ps1` 抓帧，状态行显示"抓帧中…"；
3. 提取层（MVP 可空）读取画面填 state；存疑字段进 `unresolved`；
4. 面板刷新各区域；羁绊断点由本地查表算好标注；
5. 玩家核对/手动补录存疑项，点 **[发送建议]**（或抓帧后自动触发，可在设置切换）；
6. 决策接口返回建议，写入建议区，附置信度与存疑提示；
7. 玩家按建议在游戏内自行操作；面板不代劳。

### 6.2 手动兜底
- 任意状态字段可点开手动补录（下拉/输入，联想 S18 词表，支持拼音/俗称）；
- 识别失败、画面被遮挡、视角非备战正面时，直接走手动录入；
- 手动修改过的字段标"手动"，避免下次抓帧覆盖时误改（可设"锁定此字段"）。

### 6.3 存疑与失败处理
- 抓帧黑屏 / 窗口未找到：提示"未检测到 League of Legends 窗口，请确认游戏在 main 桌面"；
- 提取层超时：回退整帧交云端看图；仍失败则保留状态供手动录入；
- 决策接口无响应：保留上一条建议，提示重试，不覆盖。

## 7. 按钮 / 动作对接表

| 面板动作 | 后端调用 | 读/写 | 预期耗时 | 说明 |
| --- | --- | --- | --- | --- |
| 重抓帧 | subprocess 调 `capture-lol.ps1` | 只读屏幕 | 稳态 ~0.15s（首轮 .NET 预热 ~0.38s） | PrintWindow 优先，黑屏回退 CopyFromScreen |
| 本地提取 | 提取层接口 `extract(frame) -> state` | 只读本地图 | 待实测（OCR 秒级内；小模型数秒） | MVP 可空实现，回退云端看图 |
| 羁绊断点校验 | 本地词表 + 断点规则 `verify_traits(state)` | 纯计算 | 毫秒级 | 不靠模型口算 |
| 发送建议 | 决策接口 `decide(state, frame?)` | 联网（云端） | 现状全链路 8~11s | MVP 贴文本；后期接 agent |
| 手动补录 | 面板表单 → 覆写 state 字段 | 本地状态 | — | 可锁定字段 |
| 设置 | 本地配置文件 | 本地配置 | — | 识别开关、自动触发、决策接口选择 |

## 8. 状态与耗时提示

- 面板必须有明确的进行态：抓帧中 / 识别中 / 思考中，避免看起来像卡死；
- 各阶段显示耗时（抓帧 / 提取 / 决策分段计时），便于后期定位瓶颈；
- 现状参考耗时：抓帧 0.15s + 整帧回传 6~9s + 云端理解生成数秒 ≈ **8~11s**；混合架构落地后以实测为准；
- 建议区标注整体置信度（高/中/低）和存疑字段数量。

## 9. 技术选型（MVP）

| 层 | 候选 | MVP 推荐 | 理由 |
| --- | --- | --- | --- |
| 面板 GUI | Tkinter（Python 标准库）/ PySide6 / PowerShell WPF | **Tkinter 起步** | 零额外依赖，最快搭出可用骨架；本机 Python 3.13 已确认 |
| 抓帧 | 现有 `capture-lol.ps1` | 沿用 | 已实测可用；面板以 subprocess 调用 |
| 本地提取 | Windows 自带 OCR → 专用 OCR → 3B 小 VLM（分级实测） | 接口预留，先空实现 | 准确率/耗时未实测，达标后接入 |
| 赛季词表 | TFT_Spider S18 快照（棋子/羁绊/装备/符文） | 接入本地 JSON | 官方口径，用于归一化与联想 |
| 决策 | 云端对话（MVP）→ 本地 FastAPI agent（后期） | 抽象 `decide()` 接口 | 面板不绑定具体实现 |
| 配置 | 本地 JSON（`panel_config.json`） | — | 存开关、窗口位置、字段锁定 |

> 备注：本机 Python 当前无 PIL / numpy / cv2 / pywin32；Tkinter 起步不依赖这些。后续若上 PySide6 或视觉模型，再按实测装依赖。

## 10. 与现有产物对接

- **`capture-lol.ps1`**：面板只调用，不改其只读语义；输出帧固定 `%TEMP%\lol_frame.jpg`。
- **参谋手册**：面板字段口径、节奏判断、两套主打打法与手册保持一致。
- **混合架构草稿**：第 2 节字段分类、第 3 节结构化模板、第 4 节模型选型、第 5 节待实测项，与本设计稿一一对应。
- **词表素材**：落地时从 TFT_Spider `seasons/s18/tft_data/tft_processed_data.json` 取标准名/费用/羁绊；图标库留作模板匹配素材（P1）。

## 11. 分期落地

### P0（MVP，先闭环）
1. Tkinter 侧边栏骨架：状态行 / 商店 / 羁绊 / 建议区 / 备注栏；
2. 调 `capture-lol.ps1` 抓帧；
3. state 对象 + 手动录入 + 字段锁定；
4. `decide()` 接口接云端对话（贴 state 文本 + 必要小图）；
5. 羁绊断点本地查表标注；存疑字段置灰进 `unresolved`。

### P1（提取层落地后）
1. 接入本地 OCR / 小模型，自动填状态行、商店、羁绊；
2. 场上/备战席识别（身份/星级/装备），局部小图回传兜底；
3. 目标阵容卡片 + 站位建议；装备分类面板。

### P2（增强，可选）
1. 对手信息识别与对位建议；
2. 本地 FastAPI agent（羁绊复核 + 查表 + 服务端二次校验）；
3. 面板美化、快捷键、对局历史记录；评估是否升级 B（本地 Web 面板）或 C（桌面应用）。

## 12. 风险与未决项

| 项 | 现状 | 处置 |
| --- | --- | --- |
| 本地 OCR 中文小字号准确率 | 未实测 | P0 后第一批实测；不达标回退云端看图 |
| 对局内 DX 渲染下 PrintWindow 是否黑屏 | 大厅已验证，对局内未测 | 脚本已有黑屏回退 CopyFromScreen；进对局实测 |
| 小模型识别棋子/装备可行性 | 未实测 | 按草稿第 4 节分级选型，先 OCR 后 VLM |

| 赛季数据版本 | S18 快照 16.18 | 落地前核对客户端当前版本，版本更新只换数据包 |
| 本机环境 | 当前会话在云主机，本机文件暂不可写 | 切回 Windows 本机后再建面板工程 |

## 13. 验收标准（P0）

- [ ] 面板在 main 桌面打开，侧边栏形态，不切 PIP；
- [ ] 点抓帧可调起现有脚本，成功拿到当前帧；
- [ ] state 字段可手动录入、可锁定、存疑置灰；
- [ ] 羁绊断点由本地查表给出达标/差额，不依赖模型口算；
- [ ] 发送建议后建议区展示云端结论 + 置信度 + 存疑清单；
- [ ] 全流程无任何模拟键鼠、无内存读取、无提权动作；
- [ ] 分段耗时可见，失败有明确提示与兜底路径。
